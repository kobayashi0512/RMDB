# mBRSET 现实可行解决方案：数据持有方联合运行

## 判断

如果个人 credentialing 无法通过，不能继续把“个人 PhysioNet 申请”当作主要方案。mBRSET 原始图像和患者级临床标签没有合法的公开镜像，GitHub、Kaggle、网盘和所谓 MESA images 均不能替代授权数据。

## 最现实的路线

寻找一名已经拥有 PhysioNet credentialed access 的导师、医院研究者或正式合作作者。数据留在对方的受控机器上，本仓库只提供冻结代码和配置：

1. 合作者取得或确认 mBRSET 访问权；
2. 合作者在本地运行 RMDB–BiRAP 的固定提取器和 `run_reverse_m0_m6_cv.py`；
3. 合作者只返回预先约定的聚合结果：OOF 预测、AUROC、AUPRC、Brier、校准指标、配对 bootstrap CI 和审计摘要；
4. 原始图像、患者表、单患者预测和任何可回溯中间文件不离开对方受控环境；
5. 以正式合作方式共同署名，并在论文中声明数据由授权合作方在受控环境内分析。

这不是共享账号，也不是绕过 DUA；它是由有权限的数据持有方执行固定分析。

## 联系 mBRSET 作者的备选路线

可向 mBRSET 原作者团队发送简短合作请求，说明：研究问题、冻结协议、所需输出、不会索取原始数据、只需要他们在受控环境运行代码并返回聚合结果。作者不能把数据直接发给个人，但可以决定是否接受分析合作。

## 如果找不到数据持有方

论文必须把临床层级降级为 mBRSET 内部探索性结果，主张限定为：

- 像素测量准确性；
- 表型重复性；
- 跨域测量运输边界；
- 结局盲的逆向失效追踪。

不能声称独立外部临床确认，也不能把 mBRSET 的内部关联写成已验证数字生物标志物。
